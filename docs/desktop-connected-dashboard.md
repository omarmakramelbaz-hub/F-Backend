# Explicit connected dashboard

The native **الداشبورد المتصلة كاملة** menu opens the original server dashboard, including account credentials, payment/provider configuration and other actions that require the server. It uses the signed-in browser session and original forms. This mode does not add desktop command fields or bounded reconciliation headers to those forms.

Each original write and native receipt fetch instead carries a paired native connected device/token proof. The server verifies that the actual session on that same request belongs to the current enabled enrollment actor; a separate earlier session probe cannot authorize a different captured cookie. Renderer-supplied proofs are stripped, and native proofs never reach another origin. Native print fetches use a one-use in-memory marker that is removed by the request interceptor before transmission. URL fragments are removed before binding to the actual HTTP URL. A missing, reused or mismatched native proof marker cancels the request instead of forwarding an unguarded server action. Request/audit metadata retains only the enrollment token hash, never this transport token. The original sign-in route may restore an expired server session; subsequent work requires the enrolled actor.

The authenticated session endpoint must also advertise the exact integer `connected_request_protocol: 1`, derived from the installed same-request guard. A matching actor alone cannot activate full connected mode on an old server that would ignore the paired proof. Every business write and native print preflight repeats this capability check, including after restart with an existing central-mode latch. Missing, zero, unknown, string and null protocol values fail closed.

For a prepared device, enter from a settled dashboard home page. The application synchronizes its local queues, refuses unresolved conflicts, imports a coherent current snapshot, acquires the local database write fence, checks the enrolled server actor and durably records the exact device, enrollment token hash, actor, source, schema and active generation. Scheduled refreshes and restart preserve the chosen connected mode. The native menu is the only entry point; remote pages receive no mode-switch or connected-review IPC.

Before a known server mutation leaves the device, native encrypted metadata records its UUID, original HTTP method and path, creation time and enrollment/source/generation binding, then flushes the dirty/pending state. Bodies, query strings, passwords, provider secrets and browser cookies are not recorded. Known mutating GETs and consuming print fetches use the same guard. HEAD cannot execute those actions. Route classification accounts for Laravel's decoded path and trailing-slash aliases. Ordinary admin browsing conservatively marks the local snapshot dirty before transmission.

Print GET coverage includes all four original order-board sources (`legacy`, `store`, `service`, `partner_service`): `OrderBoardController::print()` calls `OrderBoardPrinting::issue()` and can insert the invoice issuance audit in `branch_operation_commands`. The legacy `print-pdf`/`download-pdf` routes call the same issuance service. Takeaway receipt printing and paid dining/phone tickets can consume the initial-print grant; kitchen, delivery-batch and shift print/receipt paths are conservatively guarded as well. Print-job claims/completions are original POST requests and use the general admin-write guard. Daily-report PDFs, contract PDFs, expired expense printing (410) and job-list GETs were checked separately; they do not issue an invoice or consume a print grant.

A received response produces a separate `response-received` observation; it does not assert a business commit or provider delivery. A lost response retains its pending uncertainty across restart. The native **مراجعة نتائج العمليات المتصلة** menu lets the enrolled actor review the result on the server and record a distinct `human-reviewed` audit decision. That decision never fabricates a committed/cancelled server receipt and never resends the original request. The original request identity remains immutable. The decision is flushed before pending uncertainty can clear, so interruption between those writes is recoverable and idempotent.

**العودة لنسخة الجهاز بعد التحديث** requires the current enrolled actor, settled windows and a complete coherent snapshot. Dirty state clears only after that snapshot succeeds. Unknown outcomes must first be reviewed or receive their actual response. Failed review persistence, changed enrollment/source/generation, changed actor and failed snapshot keep the device local database fenced. An interrupted return accepts only its exact durable previous/next generation receipt.

The connected mode requires internet access. These source-level tests do not certify production activation, a packaged Windows installer or physical printer output.
