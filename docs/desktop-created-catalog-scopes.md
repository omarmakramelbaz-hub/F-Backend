# Created GO catalog scopes

A GO owner created through the original reviewed desktop form can subsequently edit that owner's original catalog. This is a catalog capability only. The persisted `desktop_dashboard_devices.branches` remains the immutable financial BASE; the original local POS selector and direct branch resolver both require that BASE.

`desktop_dashboard_created_scopes` is an additive InnoDB origin ledger. Each record binds the device, enrollment, creator account identity, command UUID, exact `go-stores.store` route, original local owner ID, canonical owner ID, account/profile creation timestamps and typed public creation receipt. Its stored evidence is encrypted with the current application's key. The accepted local journal or native remote outcome and the grant commit in the same SQL transaction. A missing origin receipt, altered descriptor, changed owner identity or different enrollment fails closed.

The three creation aliases are `menu_store_owner`, `dashboard_user` and `wallet_account`; they identify the same generated account. A later original catalog command uses the creator's typed owner reference and dependency. Central allocation may choose a different integer without adopting an unrelated account with the same local ID.

`structural()` retains authenticated recorded labels, including dormant targets, so independent complete-account and settings authority can validate its administrative cohort. `effective()` exposes only live canonical catalog targets for which the actor retains the original current catalog list/edit rights. `catalog()` checks those rights and the current account/profile identity before allowing an original catalog action. A recorded catalog capability supplies neither global administrative permissions nor financial branch authority.

Bootstrap transports explicit financial `enrollment.base_branches`, bounded public creation receipts, and coverage digests for the original grant set, structural branches and effective branches. Password values/hashes, bearer credentials and stored server ciphertext are excluded from the grant evidence. Import validates the typed device/enrollment/route/command facts and actual target identity, then encrypts the public evidence under the local profile key. Dormant origin evidence remains structural and does not authorize a replacement same-ID target.

The prepared generation's `local_state.branches` and coverage remain unchanged after local creation. Later local capabilities derive from their committed journal receipts; the original bootstrap subset remains bound to the snapshot digests. This preserves the existing native startup source, media and preview-scope checks. Refresh installs a separately verified generation and leaves the permanent print binding and financial BASE unchanged.

## Acceptance

`tests/desktop_dashboard_runtime/created-scopes.php` runs against disposable MariaDB with the captured deployed schema and the actual original Laravel controllers. It covers original creation and dependent profile editing, central ID drift, native connected creation, current permission revocation/restoration, atomic rollback, public receipt transfer and local reencryption, staging import verification, independent PHP restart, the actual native startup verifier, current account/settings authority, descriptor tampering and financial BASE/print binding preservation. `user-accounts.php` uses persisted enrollment records for its independent authority tests.

This migration does not create financial scope for a new branch. New-owner POS, cash, payroll, till, order quote and print authority require a separate reviewed financial enrollment contract.
