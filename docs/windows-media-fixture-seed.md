# Windows media fixture successor

Preview37 is immutable and remains unpublished after its mandatory native
Windows check failed. The independently run Windows probe proved that the
temporary `RUNNER~1` alias names the same directory as its canonical path. The
original native media helper rejected the lexical alias before making a request;
the canonical path succeeded, and a junction was rejected without modifying its
target. The helper bytes were unchanged throughout the probe.

CORE `4e0c33197b6d9cd635e3396e1edbf567bfb3a020` is a sole child of the
previous seed. Exactly three test fixtures canonicalize directories that the
fixtures themselves create. Every application and `desktop-pos/src` tree is
identical. SEED `e64e69667198b7dceddd4dfe516d963f43bbae27` is its sole child
with only the existing three policy files updating the CORE reference. All
mandatory checks remain present.

The pinned root entry changes five private watcher slots: unit, clean seed
checkout, state, rollout hold, and configuration, in that order. Configuration
is last. It never writes application files, filesystem modes, SQL, database
state, or historical rollout audits. Before switching, it verifies the original
completed application audit, all 17 approved payment files and their original
inode metadata, source fingerprint `41172bad…`, complete inventory `de5ac407…`,
the unpublished Preview37 lease, and its exact candidate tree. A prior metadata
reconciliation is accepted only with its complete immutable proof.

The new private intent seals these observations and both sides of every inode
exchange. Recovery classifies every active and retained slot before reversing
any exchange. Unknown replacements fail closed. A legitimate rename changes
ctime; a rolled-back retry recognizes the exact retained transaction, original
inode, bytes, mode and mtime before reusing its sealed historical observations.
Existing audits are never edited to make a check pass.

The state transformation preserves counter37, last remote revision, floors,
dependency guard and all publication history. It replaces only the base seed,
observed snapshot and desired candidate. The ordinary worker allocates38 once.
Polling accepts only that exact38 candidate, its source inventory and remote
lease, with no CI failures, backoff, blocked state, or build retry. Failed CI
stops the command; the command does not allocate another version.

The `--complete` wrapper keeps the timer paused through genuine Windows CI
artifact collection, employee/browser receipts, authorization and publication.
It waits for each new worker invocation, retains recovery files on failure, and
never kills a running worker. It resumes automatic updates only after verifying
the exact38 canonical publication, durable state/history, retained acceptance
proofs and retired hold. A completed retry performs these checks and resumes the
timer without constructing a new candidate.

Entry modes are `lease`, `prepare`, `status`, `authorize` and `verify`. Only
`prepare` changes seed slots. Only `authorize` writes the existing gate's
authorization. `lease`, `status` and `verify` are read-only; private candidate Git
objects are fetched by the wrapper into its own bare cache.
