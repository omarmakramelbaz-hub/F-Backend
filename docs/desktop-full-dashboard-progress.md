# Original dashboard local runtime — implementation checkpoint

The requested product is the complete original dashboard in an installed Windows application: the same Blade pages, account permissions and business services, local operation during an outage, and complete reconciliation when service returns. The released 0.2.1 installer does not implement that product. This checkpoint is unfinished and must not be described or deployed as a completed full offline dashboard.

## Implemented and verified

- The complete original Laravel 8.83.29 application boots with its original routes in a private desktop storage directory. Production environment files and caches are excluded.
- Original business changes and encrypted command records commit in the same InnoDB transaction. A forced journal insert failure rolls back stock and financial changes.
- A separate account enrollment credential retains current server branch and account authorization. Revocation is checked before replaying an old result.
- Server imports dispatch to original business services, deduplicate stable command UUIDs, and map locally created entity IDs to server IDs. Nine linked flows are verified: goods receipt, cash sale, approved cash expense, employee creation, attendance, payroll advance, shift closing, payroll closing and payment confirmation.
- Four additional catalog actions invoke the original category/product controllers, permission middleware, FormRequests and repositories. Original form redirects and validation errors are preserved. Category/product IDs and portion features reconcile despite integer ID collisions. Revoked permissions and changed server rows reject an update without discarding its local command.
- Shift import compares the complete mapped financial review before reissuing its server HMAC. The local and server application keys are different. Local secrets do not become production secrets.
- Payroll closing compares the mapped employee, salary totals, attendance and entry facts before issuing the original server preview fingerprint. Database-local attendance/audit IDs are excluded; actual entry/employee references and semantic revisions are retained. Changed server attendance rejects the close without a server payroll or payment. Lost local shift/payroll replies reuse their encrypted approved facts, including the same typed dependencies, after the first operation changes the ledger. Original payroll payment remains an accounting confirmation, rather than a bank transfer or a cash-drawer movement.
- Initial data export uses explicit table and branch rules and a consistent read transaction. Other branches, device journals, pairing credentials and server sessions are excluded. Only the enrolled user's password hash is retained for the original login mechanism; other included accounts cannot log in.
- Import validates data and schema hashes and foreign references in a new local staging database. Setup refuses to overwrite a populated database. The imported database gets its own empty encrypted journal.
- The supplied production inspection identified 106 existing tables on deployed commit `cedd72355a853d99ea0152f0e4091e3b59716126`, PHP 8.2.34, Laravel 8.83.29 and MariaDB 10.11.19. The exporter now covers those reviewed table structures, with explicit empty credential/queue schemas and scoped business rows. Foreign-key parent closure resolves legacy cycles without automatically importing unrelated financial ledgers. Safe original settings are retained; the platform owner's balance is excluded from a branch dataset.
- The original branded login authenticates the imported enrolled account through the unchanged controller. Actual HTTP tests render original home, takeaway, phone, dining, inventory, employee, expense and owner catalog pages and serve their original styles/navigation scripts locally. Calculating a price through original POST endpoints works without queuing a write. Uncovered GET mutations are blocked by a real read-only transaction.
- Original admin layout, catalog, subscriber, order-card and report dependencies now use a verified local mirror in desktop mode. It contains 143 public assets, the original Almarai fonts, unchanged Font Awesome integrity bytes and the original CKEditor 4.14.0 standard runtime with Arabic/English translations. Source/cached hashes and upstream licenses are retained. Packaging refuses an incomplete or altered cache; Git preserves its bytes on Windows. Normal server pages keep their original URLs.
- Journal timestamps explicitly use UTC on the wire and during reconciliation, preserving the sale hour independently of the original Cairo UI timezone.
- The actual loopback PHP HTTP gateway requires the application credential. Native outbox control needs an additional credential that is never injected into dashboard pages. Browser headers cannot acknowledge a sale. Private headers are stripped from external requests.
- Electron owns a PHP/MariaDB supervisor and native reconciliation loop. Shutdown drains accepted work before stopping local services. Local activation requires a completed preparation marker, which this incomplete checkpoint does not issue.

## Validation

`tests/desktop_dashboard_runtime/native-run.py` starts and deletes a disposable loopback MariaDB instance and runs the complete original Laravel application. The current fixtures pass **125 checks** (78 core and 47 complete-schema/catalog checks), including actual scoped export/import, financial rollback, original HTTP login/pages/forms, ID collisions, lost responses, different application keys, permissions, revocation, conflicting catalog revisions and protected HTTP control. They do not connect to production. The 106-table structural fixture retains the inspected column types and foreign keys; its defaults and indexes are synthetic, rather than an exact production database dump.

Electron's embedded Node test runner passes **37 tests**, including original limited-POS regressions, reconciliation ordering, lost acknowledgement retries, shutdown, printer response contracts and local header isolation. These are Node and mocked Electron contracts, not a physical Windows installation or printer test.

`.github/workflows/desktop-dashboard-tests.yml` uses a hash-verified MariaDB 11.4.13 archive and the original PHP application on Windows. No new Windows installer has been generated for this checkpoint.

## Deployment boundary

`desktop_dashboard.enabled` and `desktop_dashboard.local` default to false. Normal server dashboard requests keep their existing behavior. The prior POS root deployment helper does not apply the new full-dashboard journal migration or enable this feature. Do not run it to claim this checkpoint is enabled. Preserve production data and first review the exact deployed commit and schema.
