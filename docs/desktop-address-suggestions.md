# Desktop address suggestion endpoint

The original `phone-orders.address-suggestions` POST now reads saved `branch_customers` addresses in Desktop local mode, after the original query validation and fresh actor/branch authorization. Central admin access additionally proves the current `order-list` grant from persisted direct/role pivots, without relying on the shared permission cache. The original account 1, admin-guard `Super Admin` role and branch-scoped admin exceptions are preserved. These checks use no write locks in the local read-only transaction.

It returns at most six stable, deduplicated address/area labels with finite, nonzero stored pins from the selected branch. Query matching and stable identities use the full normalized address/area before the display label is shortened to 400 characters. Matching is literal; customer names, phone numbers and notes are neither selected nor returned. The endpoint creates no journal command or business write and calls no map provider locally. An empty result means that no suitable saved pin was found; the operator still needs to select a location manually.

The online Photon path retains its existing explicit activation, request parameters, cache, rate limit and branch validation. Both desktop read-POST registries classify this exact endpoint as a read.

The original phone-orders UI now uses this endpoint only when the existing `data-dashboard-local="1"` page flag is present. It searches the current branch with the original same-origin read POST and cancellation signal, accepts only saved-provider results with valid finite, bounded, nonzero pins, and resolves those returned pins without Google or another map provider. The list and empty state explicitly identify saved addresses; labels are used as address text without guessing a separate area. The local map is hidden and its picker is never constructed, so this flow starts no Google SDK, Places, geocoding or OpenStreetMap tile request. The ordinary online Google UI remains unchanged.

Selecting a saved address clears any previously confirmed location and displays the existing delivery-cost preview. That preview does not confirm the location: the operator must review or edit the visible coordinates and press the confirmation button before continuing. The original authorized delivery quote and its hash still determine the order location and fee. Query edits, branch changes, aborts and page disposal retain the original typeahead generation guards and disabled cache. The local runtime retains its existing straight-line `pin_distance` delivery policy; map routing policy is not changed here.

This is saved-address search for one authorized branch, not general offline geocoding or an offline map. An unknown address or an empty saved list requires manually entered coordinates and explicit confirmation. It does not establish full phone-order or dashboard coverage. Full coverage remains false.
