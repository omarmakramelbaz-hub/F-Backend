# Scoped desktop row deltas

The native client posts its verified local capture index to `POST /api/desktop-dashboard/delta`. The body is opaque JSON with `Content-Type: application/octet-stream`, so global JSON input normalization does not allocate or alter the large index before this authenticated route checks its request budget. The request is limited to 64MiB, 500,000 indexed rows and 200 tables. The server response is limited to 256MiB. Oversized or incompatible requests fail explicitly; they do not fall back to downloading the entire account.

The index contains device, actor and the executing program's source identity. Each table describes its normalized structural DDL hash and a multiset of canonical row hashes with duplicate counts. It contains no SQL or account row values. Scope, redaction, enrollment, parent closure and media capabilities come exclusively from the existing authenticated bootstrap export. This first protocol scans scoped rows on the server to calculate differences; it is not a database change log.

Ordinary responses retain bootstrap metadata and replace each table's rows with additions, removed hash counts and a target multiset hash/count. Canonical numeric identities use SQL types and IEEE754 storage bytes (binary32 for FLOAT, binary64 for DOUBLE), independent of PHP JSON precision or PDO's widened representation. SHOW CREATE resolves REAL aliases and FLOAT(p) to the physical type; the codec also handles the 24/25 precision boundary for single-argument FLOAT(p). Added SQL FLOAT/DOUBLE values travel as lossless numeric strings after rounding to their storage width and regain their SQL type during private staging import. Values that would overflow or underflow to zero are rejected. Passwords of every other user are both hashed and reconstructed as a fixed invalid offline-login marker. The actor's own hash is retained.

Only the mutable table-level `AUTO_INCREMENT` counter is excluded from structural DDL identity. A real schema change replaces that table alone: its delta has `replace: true`, removes every verified old hash/count and supplies all currently authorized target rows. A newly introduced table has an empty prior index. Retired allowed tables are omitted from the fresh target generation. Unknown table names, client DDL and client row values are rejected. Empty new/replaced/retired tables still count as structural changes in `delta_summary.changed_tables`.

The local reconstructor must verify every captured old table against the capture receipt using its original DDL and original trusted coverage before applying any response. `applyReplacement` requires the complete verified removal multiset and verifies all additions against the target DDL, target count and canonical hash. A normal four-field delta may use the same replacement check only when the trusted caller proves that old and new coverage select different column projections; the optional PHP argument authorizing this case is never read from the network. This handles restricted pending-vendor eligibility without retaining omitted private columns.

Reconstruction and existing import/FK validation run in a new empty private database. They never overwrite the active cashier database. Network transfer and media verification finish before the final short generation fence; an intervening local business operation causes deferral rather than losing that operation.
