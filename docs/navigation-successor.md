# Prepared rollout navigation correction

This immutable package adds a narrow entry for the already prepared, unpublished Preview36 rollout. It retains the cd35 seed, installed runtime, configuration, checkout, control-plane state, counters, publication history, sequence floors, employee schema and business data. Only the reviewed `dashboard-navigation.js` and an existing optional source manifest change. The original employee view location is retained; the later employee modal work is excluded.

Run the pinned wrapper with `PACKAGE_COMMIT --prepare`. It pauses the timer, waits for the current worker to finish, and acquires the existing nonblocking watcher lock. Before changing files it recognizes the exact old source, original42 application pins, runtime/unit, pushed candidate36, remote lease and unauthorized old hold. A private journal binds the old/new held identities and control-plane observations. The hold remains present during every exchange. On ordinary failure the source is restored before the original hold. An uncertain interruption keeps the timer paused and retains its journal for review; it never certifies rollback from missing evidence.

After successful preparation the wrapper requests exactly one held worker tick. The existing watcher observes the navigation source change and allocates its next monotonic preview, normally37. This entry never rewrites a counter, desired candidate, version, seed, configuration or database. Repeating preparation after committed correction reuses the actual durable successor; it does not reset it to36 or37.

The wrapper's `PACKAGE_COMMIT --publish /var/lib/go-erp-live-updates/pending-program-acceptance.json` mode consumes the real successor CI evidence through the installed exact gate and artifact verifier. It requires the new source/inventory and actual successor candidate, rejects stale36 acceptance, and authorizes only that release. The worker independently authenticates the GitHub run and artifact provenance before publication. No test fixture or command manufactures production acceptance evidence.

An authorized publication starts one worker and resumes the normal timer. A completed publication retry verifies retained evidence and durable publication before resuming the timer without another worker, including a timer left paused by a previous interruption. A completed preparation retry preserves the prior timer state. Future updates return to the existing automatic policy after the one rollout hold is independently retired.
