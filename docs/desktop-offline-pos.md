# برنامج فسخانستا للكمبيوتر — نسخة تجريبية 0.2.0

برنامج ويندوز x64 قابل للتثبيت يفتح الداشبورد الأصلية كاملة مباشرةً، بنفس صفحاتها وشكلها وحسابات الدخول وصلاحيات الأونر والأدمن والفروع. تستخدم جميع شاشات الداشبورد الحالية السيرفر الفعلي؛ لا توجد نسخة مختصرة أو تقارير تجريبية بديلة. يدعم أيضًا الطلبات المحلية والطباعة بعد ربط الجهاز وتنزيل المينيو أول مرة، ويرفع العمليات تلقائيًا عند عودة الاتصال.

## الاستخدام

1. نزّل ملف التثبيت وأغلق النسخة القديمة إن كانت مفتوحة، ثم ثبّت البرنامج واترك خيار «فتح الداشبورد الآن» مفعّلًا في خطوة Finish. يحافظ التحديث على بيانات الجهاز وربطه وطلباته السابقة.
2. افتح البرنامج؛ تظهر الداشبورد الأصلية مباشرةً، وسجّل الدخول بحسابك المعتاد. جميع الصفحات والأزرار الحالية متاحة وفق صلاحيات ذلك الحساب.
3. لتجهيز العمل أثناء انقطاع الاتصال، افتح «برنامج الكمبيوتر» من الداشبورد، واختر الفرع واكتب اسم الجهاز وأنشئ كود الربط. الكود صالح لعشر دقائق ولمرة واحدة.
4. من قائمة البرنامج اختر «الطلبات المحلية والطابعة»، واكتب رابط الداشبورد وكود الربط أثناء وجود الإنترنت. الجهاز المرتبط سابقًا لا يحتاج إعادة ربط.
5. من قائمة البرنامج اختر «اختيار الطابعة». يمكن استخدام طابعة ويندوز الافتراضية. طباعة فواتير الداشبورد ترسل إلى الطابعة مباشرةً بعد تحديث الربط على السيرفر.
6. عند انقطاع الاتصال، تكشف النسخة المحلية للطلبات تلقائيًا. الطلبات والتحصيل الكاش والطباعة تحفظ محليًا وتُزامن عند عودة الإنترنت. لا يتيح البرنامج بيع صنف بسعر غير مضبوط أو بصفر.
7. للعودة إلى الداشبورد الأصلية، اختر «الداشبورد كاملة» من قائمة البرنامج، أو اضغط زر «الداشبورد» في شاشة الطلبات المحلية.

## ما تتضمنه هذه النسخة

- أصناف الفرع وأسعار الخيارات والأوزان، مع ضريبة وخدمة محفوظتين في نسخة المينيو.
- حتى خمس مسودات فواتير مفتوحة، وحفظ الطلبات على الجهاز بعد إغلاق البرنامج وإعادة تشغيله.
- إرسال محلي للمطبخ، وطباعة طلب الحساب، وتحصيل الكاش، وإعادة الطباعة.
- تعديل الطلب بعد إرسال المطبخ مع منع إلغائه، وقفل المحتويات بعد طباعة طلب الحساب.
- اسم العميل ورقمه وعنوانه وقيمة توصيل يدوية لطلبات الهاتف، واسم الطاولة للصالـة.
- سجل عمليات مستقل في صفحة «برنامج الكمبيوتر» بالداشبورد، يتضمن وقت التنفيذ ووقت المزامنة.
- الفواتير المحصلة تدخل جداول المبيعات والكاش الحالية، وخصم المخزون يحدث في المعاملة نفسها.
- أرقام عمليات ثابتة تمنع تكرار التحصيل والمخزون بعد فقدان رد السيرفر أو إعادة تشغيل الجهاز.
- الفاتورة المفتوحة تحتفظ بنسخة أسعارها ووصفاتها حتى لو تغيّر المينيو لاحقًا.
- الحفظ يتم قبل إرسال أمر الطباعة، وفشل الطابعة لا يعيد التحصيل.
- رمز الجهاز محفوظ بتشفير حساب ويندوز؛ الداشبورد يستطيع إيقاف ربط الجهاز.
- نسخة احتياطية يدوية من قاعدة الجهاز. إعادة تثبيت البرنامج وإزالته تحفظان قاعدة الطلبات الموجودة خارج مجلد البرنامج.

## حدود النسخة التجريبية

الداشبورد الأصلية بجميع صفحاتها متاحة داخل البرنامج أثناء الاتصال، بما فيها التقارير والمصروفات والمخزون والموظفون والرواتب والإعدادات. هذه الصفحات ما زالت تعمل على السيرفر وتحتاج الإنترنت. التشغيل المنفصل في النسخة الحالية خاص بطلبات الكاشير والطباعة والتحصيل، وليس مزامنة محلية كاملة لكل شاشات ERP. لا تظهر عملية سيرفر فاشلة كأنها حُفظت محليًا، ولا تُعاد POST خاصة بالمصروفات أو الرواتب أو الإعدادات دون تأكيد حقيقي من السيرفر.

التصميم الحالي لجهاز كاشير مستقل؛ لا يتبادل الطلبات بين أجهزة الفرع عبر شبكة محلية. سجل الطلبات غير المحصلة يظهر في صفحة «برنامج الكمبيوتر» بعد المزامنة؛ لا يربط الطاولة المحلية تلقائيًا بحجز طاولة عبر شاشة الصالة الحالية.

طلبات التطبيقات الجديدة، والخرائط، والدفع الإلكتروني تحتاج الإنترنت. المصروفات وتقفيل الوردية وإدارة الموظفين تتم من الداشبورد؛ أكمل مزامنة عمليات الجهاز قبل التقفيل. يحفظ التقرير يوم البيع الأصلي، وتُسجَّل حركة الخزنة عند الاستيراد حتى تدخل في التقفيل التالي إن كان السابق قد انتهى.

النسخة غير موقعة رقميًا. تم بناء ملف التثبيت وفحص المحتويات واختبار الحفظ والمزامنة والاستيراد والواجهة. ظهر تثبيت وفتح النسخة 0.1.0 على ويندوز فعلي في لقطة المستخدم؛ اختبار قبول النسخة 0.2.0 والداشبورد كاملة والطابعة الفعلية ما زال مطلوبًا. لا توجد بيانات تجريبية داخل ملف البرنامج.

## حالة الربط

تحديث الربط متاح للمراجعة على فرع مستقل. تشغيله على السيرفر يحتاج تطبيق ملفات الربط والمايجريشن ووضع ملف تثبيت ويندوز وتفعيل الإعداد أدناه. ملف البرنامج يحتاج مسارات السيرفر الجديدة قبل أن يستطيع الربط وتنزيل المينيو.

المستودع: `omarmakramelbaz-hub/F-Backend`.
الأساس: `2c107464d5fbca7032bced5a184d4c8015656b4f` من `codex/unified-app-orders-20261003`.
فرع الربط: `codex/desktop-offline-pos-20261007`.

## تفعيل السيرفر بعد الموافقة

يوجد أمر تفعيل مخصص لحساب root في `deployment/apply_desktop_pos_root.sh`. يأخذ رقم الإصدار المراجع ورقم HEAD الحالي للسيرفر، ويوقف التنفيذ إذا تغير السيرفر أو الفرع أو وجدت تعديلات متتبعة. يحفظ نسخة من قاعدة البيانات والشيفرة والإعدادات قبل التطبيق، ثم يضيف جداول الربط ويختبر المسارات والمصادقة. يستخدم حساب التطبيق `fasakha` ويحافظ على وضع كاش الإعدادات. عند فشل التفعيل يعيد الشيفرة والإعدادات السابقة ويحتفظ بالجداول والعمليات الجديدة.

الحفظ يحتاج `mysqldump` أو `mariadb-dump` على السيرفر. لا تظهر بيانات اتصال قاعدة البيانات في الأمر أو المخرجات. النسخة الاحتياطية خارج مجلد الويب وبصلاحيات خاصة. إذا لم يُرفع ملف ويندوز بعد، يمكن ربط النسخة المثبتة بالفعل؛ تنزيل البرنامج من الداشبورد يتاح بعد رفع الملف.

1. خذ نسخة من قاعدة البيانات وحالة الشيفرة الحالية، وراجع اختلاف السيرفر عن الأساس أعلاه.
2. طبّق الملفات الواردة في حزمة الربط على فرع مراجعة، ثم راجع تغييرات الصلاحيات والمزامنة. لا تستخدم reset ولا تستبدل تعديلات أحدث.
3. نفّذ المايجريشن الجديدة فقط، بحساب تشغيل التطبيق:

```bash
php artisan migrate --path=database/migrations/2026_10_07_210000_create_desktop_pos.php --force
```

4. افتح «برنامج الكمبيوتر» بحساب الإدارة المركزي، واختر ملف `Fasakhansta-POS-Setup.exe` من جهازك ثم اضغط «رفع البرنامج». يظهر تقدم الرفع، ويُتاح التحميل بعد فحص الملف بالكامل. لا يحتاج مدير ملفات استضافة. يمكن أيضًا وضع الملف يدويًا في `storage/app/desktop-pos/Fasakhansta-POS-Setup.exe` مع صلاحية قراءة لحساب التطبيق.
5. أضف `DESKTOP_POS_ENABLED=true` إلى إعدادات بيئة السيرفر، ثم حدّث كاش الإعدادات والمسارات بالطريقة المعتمدة للمشروع.
6. اختبر على جهاز فرع واحد: ربط وتنزيل المينيو، فصل النت، حفظ وإرسال وطباعة وتحصل فاتورة، قفل وإعادة فتح البرنامج، إعادة النت، والتحقق من فاتورة واحدة وحركة كاش واحدة وخصم مخزون واحد.
7. راجع الفواتير ذات الأوزان والخيارات والإجمالي والهوامش والطابعة الفعلية، ثم اعتمد تجربة الفرع قبل تعميمها.

عند الحاجة لإيقاف التجربة، عطّل `DESKTOP_POS_ENABLED` مع الاحتفاظ بجداول المزامنة وقاعدة الجهاز. لا تحذف العمليات المحلية أو لقطات المينيو القديمة؛ قد تكون مرتبطة بفواتير لم تُزامن بعد.

## بناء البرنامج واختباراته

```bash
cd desktop-pos
npm ci
npm test
npm run build:win
```

البناء يستخدم Electron 44.6.0 وSQLite المدمج في Node الخاص به. التثبيت لكل مستخدم، ويوفر اختصارًا على سطح المكتب. ملف البناء النهائي في `desktop-pos/dist/Fasakhansta-POS-Setup.exe`.

اختبارات الاستيراد تستخدم قاعدة SQLite مستقلة في الذاكرة وخدمات POS والمخزون الحقيقية، وتُنفَّذ دون تحميل ملف `.env` الخاص بالإنتاج:

```bash
cd tests/desktop_pos_runtime
composer install
php run.php
```

اختبار الواجهة يستخدم Playwright مع مخزن الطلبات المحلي الحقيقي وطابعة مفصولة بالمحاكاة:

```bash
cd desktop-pos
npm install --no-save playwright
npx playwright install chromium
node test/ui-smoke.cjs
```

تغطي الاختبارات: بقاء الطلبات بعد إعادة التشغيل، فشل الحفظ دون آثار جزئية، فقدان رد السيرفر، ثبات أسعار الفواتير، منع تكرار المخزون والكاش، قفل الحساب، منع تعديل إجمالي المينيو من العميل، منع الربط بفرع آخر، وإيقاف رمز الجهاز.

## رفع ملف التثبيت من الداشبورد

الرفع متاح للإدارة المركزية التي تملك صلاحية إدارة الطلبات، وليس لحسابات الفروع. كل جلسة رفع مرتبطة بحساب الإدارة وجلسة الدخول، وتستخدم مسارات POST المحمية بالمصادقة وCSRF. يُرسل الملف في أجزاء بحجم 512 كيلوبايت، وتُعاد المحاولة عند فشل الاتصال؛ لا تحتاج زيادة حد رفع ملفات PHP أو إعداد لوحة الاستضافة المعتاد.

الملف محفوظ خارج مجلد public، ولا يُنفّذ. يُفحص الحجم وSHA-256 وفق النسخة المعتمدة في `config/desktop_pos.php` قبل إتاحته؛ عند تحديث نسخة ويندوز يجب تحديث هذين الإعدادين. الرفع غير المكتمل أو الملف المختلف لا يستبدل النسخة المتاحة. تُنشر النسخة الصحيحة بإعادة تسمية ذرية، ويُحذف الجزء السابق عند إعادة بدء الرفع، وتُنظف الأجزاء المهجورة الأقدم من 24 ساعة عند بدء رفع جديد.

اختبارات الرفع المحلية تستخدم مجلدًا مؤقتًا ولا تفتح قاعدة الإنتاج:

```bash
php tests/desktop_pos_runtime/installer.php
node tests/desktop_pos_runtime/installer-ui.cjs
```
