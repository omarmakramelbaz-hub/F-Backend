# Live messages alongside local dashboard work

After the first verified preparation, the normal dashboard continues to open on the device. Its durable business commands use the existing shared 30-second synchronization cycle. The new live messages and social comments actions do not select connected ERP mode, replace the local view, or alter this scheduler.

The two actions open the original server inbox or comments in a separate native window. Its nonpersistent session receives only cookies for the pinned enrollment server. A native request in this same session must confirm the enrolled actor, device and exact connected-request protocol before loading a live page. Every social POST repeats that check; each social request also carries the paired device proof that the server validates against the actual request's cookie actor. Neither this transport token nor the local runtime bridge is exposed to the page.

Only the original Meta/WhatsApp message, media, reply, read/hide/reaction and comment routes are allowed. Meta display-name enrichment is limited by its original controller to refreshing the scoped conversation name; it does not edit a dashboard customer. ERP mutations, conversation order dispatch, account/provider settings and OAuth connection changes are blocked. The conversation order drawers and AI configuration panels are hidden, with a visible note directing business work to the local dashboard. The message/comment controllers retain their existing request UUID and uncertain-delivery rules; the native window never retries a send or puts it on the ERP scheduler.

Static requests use an explicit route and CDN allowlist, with native headers removed. The window has no preload, Node, or IPC bridge. Navigation and redirects stay on its two live pages. Microphone capture requires a separate native confirmation and is limited to audio from the verified messages page; camera, location, notifications and other permissions remain denied.

Initial network failure displays a restricted Internet-required page with a user-selected read-only reconnect. A network failure on a loaded page adds a fixed notice without replacing its message draft. Returning Internet never resends a POST. Subsequent safe reads can reverify the social session; an expired or different actor receives fixed renewal instructions. Changing between messages and comments while one is open preserves the existing window and asks the user to close it after saving a draft.

Automatic installer application waits until the live window closes, including a final check immediately before the installation gate. Local reconciliation and server-data refresh keep their existing cadence while the live window remains open. Social identity binds the enrollment, not the changing local generation. Normal program exit closes the isolated window and clears its own session storage.

Source tests cover the separate native surface, server-cookie isolation, immediate original social routes, ERP route rejection, proof stripping, actor/protocol drift, fixed offline notices and no automatic resend. Windows installer and real provider acceptance still run against the resulting candidate before release.
