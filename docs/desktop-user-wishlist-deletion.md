# Original user wishlist deletion

This bounded increment supports only `userwishlists.destroy`, the original `DELETE /admin/userWishlistsDelete/{id}` form in the user's wishlist table. The unchanged `UserController::userWishlistsDelete` executes `Wishlist::where('id', $id)->delete()` and redirects back with its original success flash. The custom method is protected by `IsAdmin`; the controller's resource `account_type-delete` permission does not apply to it. No resource-delete, POS-write, role-name or actor app-scope requirement is added.

The original query-delete does not dispatch Eloquent model deletion events. Although `Wishlist` implements MediaLibrary, this action preserves its attached media records and files. The adapter invokes that original route, captures all five wishlist columns and its actual restaurant/user identity parents, and verifies the current enabled actor/device, enrolled F branch and current restaurant ownership before local, reconciliation or native cached replies. Server replay compares the complete before-state before deleting; independent deletion or changed relationships remain a retained409 conflict. Named `user_wishlist`, `wishlist_resturant` and `wishlist_user` references resolve dependent IDs without guessing by numeric collisions. New branch snapshots include only wishlists for their enrolled F restaurants.
