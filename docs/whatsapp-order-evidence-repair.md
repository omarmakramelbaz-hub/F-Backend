# WhatsApp order evidence repair

The production diagnostic for conversation 11 showed that manual draft 71 included the October 9 WA-0101 link probe and therefore became NONE / TEST_MESSAGE. Its post-activation customer messages were genuine order requests, but the accepted dashboard replies containing the item summary and confirmation had no native echo and were absent from the order transcript. Earlier automatic drafts recorded AI_UNAVAILABLE, whose underlying transport or validation reason had not been retained.

The repair projects cryptographically verified, Meta-accepted dashboard text receipts into the existing message cursor with the explicit dashboard_api source. The encrypted receipt envelope is not a webhook. A later genuine echo shares its canonical native message key, validates against the receipt and does not insert or rewrite evidence. Acceptance commits before separate projection, so a projection failure cannot undo a durable receipt or resend a reply.

Manual analysis in an already activated automatic configuration uses the current activation and dispatched boundaries. Historical manual review in review mode is unchanged. The probe guard remains enforced inside the selected segment. Fresh customer commitment, matching business confirmation, complete customer/location data, live catalog and open physical branch checks remain required; no order is authorized from a generic confirmation sentence alone.

Provider failures retain an encrypted, allowlisted diagnostic envelope containing fixed categories and bounded numbers. Keys, error prose, request IDs and raw provider responses are omitted. The approved gpt-6-luna uses explicit low reasoning, an 8,192-token total output allowance and a 45-second request timeout. Ten requests leave headroom under the existing 600-second worker deadline. The small greeting preflight does not establish why an earlier full transcript failed.

The seven-file publisher verifies exact live preimages or targets, protects configuration and ERP files, holds both installation locks, quiesces the existing pipelines and conditionally publishes with a private backup. It preserves activation cutoffs and effective configuration. It performs no migration, AI request, inbox consumption or order dispatch. Normal completion restores the observed timer states. Rollback after exposing an entrypoint keeps orders paused for review because an in-flight HTTP reply may still create the new evidence format.

Use the pinned apply_whatsapp_order_evidence_repair_root.sh for this release. Do not rerun activation to install it. Older Cairo/dashboard publishers retain their exact source profiles and safely stop on these newer runtime bytes; a future upgrade must explicitly incorporate this repair.

The production preflight found 20 specifically identified configuration PHP files with mode 0775. The separate normalize_whatsapp_order_config_modes.py helper removes only their group-write bit, producing 0755; it does not alter file contents, ownership, other permission bits, the environment file or the configuration cache. A private metadata journal records the original permissions and progress. The original publisher's permission and configuration preservation guards remain unchanged. Run the normalizer before the publisher; an interrupted or concurrent-change failure must stop the combined command before application publication.

Four existing read-only configuration files are owned by root: config/go_services.php, config/jwt.php, config/mail.php and config/partner_auth.php. The publisher accepts that exact ownership profile only for those paths when they remain regular files with one link and mode 0644. It retains their actual owners, modes, inodes, timestamps and contents in the configuration checks; it does not change ownership or write those files. All other configuration and runtime ownership guards remain strict.

Existing quarantine records remain an independent dispatch blocker. They are not cleared or bypassed. The observed trial also lacks a native customer location pin and a business summary repeating the customer's full address. Fixing extraction visibility does not make incomplete evidence dispatchable. Cairo virtual stores still bill delivery from their own origin while fulfillment remains at physical Shubra branch 301; other physical branches retain their existing routing.
