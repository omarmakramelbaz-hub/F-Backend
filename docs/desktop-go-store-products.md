# Original GO store product forms

`go-stores.products.store` and `go-stores.products.update` execute the original `StoreController::saveProduct` and `Catalog::saveProduct`, with their original multipart form, validation, prices, availability and ordered product options. They apply only to an existing enrolled `gs` owner. They do not create an account, change device enrollment, or enable additional dashboard routes.

Before both new work and cached responses, current locking reads require the enabled enrolled actor, original central admin/list/edit authority, exact enrolled GO owner, its recorded non-null creation timestamp, and current product ownership/request identity. The new adapter freezes this immutable owner identity separately from the existing profile helper wire format, and rechecks it even for a cached CREATE reply whose prior product was absent. A deleted/recreated owner at the same numeric ID cannot recover the old result when its creation identity differs; missing creation identity requires connected review. Reconciliation freezes the complete product row, store/owner/profession facts, revision, options and image digest. Independent changes conflict before the original controller runs. Named `menu_store_owner` and `menu_store_product` references preserve dependent edits across actual server auto-increment collisions; identifiers of other entity kinds cannot substitute for them.

New options retain the exact UUIDs generated by the accepted original form. Replay installs a bounded UUID factory only around that original controller, consumes exactly the recorded new option IDs, and restores the prior factory even on failure. Local business timestamps and the journal occurrence share one frozen instant. Existing option IDs still pass the original ownership checks; the adapter does not generate replacements for previously saved options.

JPG/PNG/WEBP uploads retain the original 5 MiB and 4096-pixel limits. Actual bytes, MIME, dimensions, filename and SHA-256 are validated and encrypted with the command. Laravel's original upload path writes an operation-bound immutable filename, independently beneath the correct local or server owner directory. Existing image versions remain untouched for order snapshots. Failure inside the root DB callback rolls back rows and removes only files whose path was confirmed absent before this command wrote it. A root COMMIT acknowledgment failure is uncertain: the bytes remain, so an image that may have committed is never removed. Such an unreferenced immutable path requires review rather than being overwritten by another command. Symlinks, other file layouts/disks, changed old bytes and pre-existing new paths fail closed.

Native reservations retain the exact original physical POST, multipart bytes, logical UUID and terminal outcome. The original controller result, full before/after facts and image proof commit with that outcome. Failed outcomes can be cancelled; delayed cancelled requests cannot later mutate a product. Repeated uploads with the same command recover the prior revision, option IDs and image. Current enrollment is checked on native cached replies and settlement.

The focused Laravel/MariaDB fixture uses genuinely separate local and central filesystems. It exercises creation, existing edits, generated/existing options, forced journal/native outcome failures, lost replies, full-row and fabricated-result conflicts, real auto-increment ID drift, dependent original forms and current enrollment. Node fixtures run the original renderer script and exact native route classifier. Windows/Edge/installer acceptance remains a release requirement, and `coverage.full_dashboard` remains false.
