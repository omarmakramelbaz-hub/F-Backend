# Original application order-board component

This component invokes the actual `order-board.action` route, middleware and `OrderBoardController`, with the existing legacy restaurant, GO store, partner-service and marketplace services. It registers only that exact route with its bounded action/financial admission below. It does not set full-dashboard coverage.

The initial cohort is the current enabled owner account, ID 1, with its complete captured financial dataset. Its current type, central ownership, account status, enrollment and each affected branch are checked before a new write or a historical reply. A stored reply additionally retains the exact source, order identity, parties and creation time; it does not require the order to remain in its earlier status. Other account snapshots mask the app balance or omit global wallet/coupon/service dependencies, so this component does not infer their missing financial facts.

Before work, the component freezes the complete original row, acceptance/courier clock, actual financial parties and balances, related ledger, calculation settings, source-specific rows, recipe inventory, stock consumption markers, current menu/portion inputs, active competition data, relevant CRM identities/source links and purchase state. Table IDs whose business identity is a composite stock key are omitted; independently generated Wallet and CRM identities have named typed outputs. Replay requires matching facts under database locks. Local and replay occurrence times must be identical. After verification maps explicit before/after references and compares the complete resulting graph, preserving IDs and all financial/lifecycle fields. Board work never renews consent; the original matching consent tuples remain authoritative, including typed prior POS evidence.

The component admits original current restaurant acceptance, branch-courier preparation, cash completion, cash rejection and verified accepted-order cancellation. Cash completion retains the actual recipe deduction, coupon/competition observer, vendor/courier commission, application balance and CRM purchase. The original accepted-order cancellation service verifies its actual wallet/payment evidence before refunding. External courier discovery remains connected: its available pool and dispatch provider state are not captured in the branch dataset. Legacy noncash rejection and completion require connected payment review; their older refund/confirmation paths have not been admitted by a route name alone. Shipping and scheduled orders are also outside this component.

GO store transitions retain their own revision, minimum-wallet, fee, cash/paid and refund-pending rules. Paid orders require exactly one matching completed original gross credit before admission. A paid gateway cancellation records the original financial reversal and pending external refund; it does not contact the gateway locally. The original connected paid rejection now requires that same actual gross credit. Wallet-held reject/cancel/complete remain connected because this retained source bundle contains no checkout hold writer or verified hold-reference contract; a held flag alone cannot prove a refund. Partner-service transitions retain their separate accepted/completed clocks. The marketplace source admits only the original unbooked searching-job rejection, recording its central message intent without creating a cancellation fee or provider dispatch. Providers and the local scheduler remain disabled by the common runtime boundary.

Competition before-facts also include the actual restaurant eligibility, all related customer order counts and subscriptions. Replay preserves only the new command's validated random draw code, checks its global collision query under the transaction and maps the new subscription ID. A missing/extra draw or reused code conflicts, rather than selecting a different winning-entry identity silently.

The board controller now requests the original browser response from nested vendor mutation methods because their mobile API resource is discarded by the board. The outer board JSON/card response is unchanged. This prevents valid dashboard preparation from failing in an unrelated mobile serializer, while preserving the request fields used by retained online courier discovery.

`order-board-component-run.php` explicitly runs the component after the 70 original cash integration checks, followed by `order-board-reconciliation.php`. Its 41 component checks exercise retained controllers, immutable replies, real recipe stock/commission/purchase and competition effects, draw identity drift, stale stock beneath an independent repeatable-read connection, rollback after completed controller work, GO cash/gateway-paid cancellation, guarded unproved held/payment/provider boundaries, legacy verified wallet refund and the two distinct service lifecycles. The independent local/server databases prove the actual shared middleware, sequential acknowledged dependencies, differing CRM/Wallet/subscription IDs, unchanged saved responses, complete after-state checks, global draw-code collision rollback, stale financial-input conflicts and current enrollment/authority before cached responses. Actual native server reservation tests cover committed replies, transport aliases, changed-body conflicts, revoked authority and cancelled delayed requests. Native browser intent tests exercise the actual original JavaScript UUID function across polling replacements, retries, account/snapshot changes and unavailable session storage. The existing board/isolation/payment/clock feature suite passes 90 tests and 885 assertions. These checks do not establish Windows execution, branch-account coverage or physical printing.

The original action form keeps one durable UUID per actor, dataset generation, exact source/order route, expected state and selected action. A lost response, DOM polling replacement or page reload reuses it. Missing dataset generation or denied session storage stops the local send before the controller. Native reservations admit exact positive-ID source/action POSTs and verify the same current original authority and identity before committed, alias and terminal replies.
