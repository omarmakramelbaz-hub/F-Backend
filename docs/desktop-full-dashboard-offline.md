# الداشبورد الكاملة على الكمبيوتر — المتطلب المعتمد

المطلوب الذي أكده المستخدم في 8 أكتوبر 2026: تثبيت برنامج يعرض نفس الداشبورد الأصلية، بنفس الشكل وجميع شاشات الحساب وصلاحياته. عند انقطاع الإنترنت تظل الشاشة نفسها، وتنفذ العمليات على الجهاز؛ عند عودته ترفع جميع العمليات والأرصدة والتغييرات إلى السيرفر، ثم يعود البرنامج للعمل المتصل. شاشة كاشير منفصلة أو مجرد فتح الموقع داخل Electron لا تحقق هذا المتطلب.

## الحالة الفعلية

النسخة 0.2.0 فتحت الداشبورد الأصلية أثناء الاتصال فقط. التشغيل المحلي فيها خاص بطلبات الكاشير. النسخة 0.2.1 تصلح خطأ `database is not open` وتنتظر العمليات الجارية عند الإغلاق؛ لا تضيف تشغيل كل وحدات النظام دون اتصال. لا يجوز تقديم أي منهما على أنها تحقق المتطلب الكامل.

تمت مراجعة مصدر النظام: 40 متحكمًا للداشبورد، و34 خدمة للداشبورد (5120 سطرًا وقت المراجعة)، و164 قالب Blade داخل `resources/views/admin`، و73 ملف مايجريشن. بعض المسارات تستخدم متحكمات API وخدمات Go أيضًا؛ هذه الأرقام ليست عدد المسارات النهائي ولا قائمة قبول مكتملة. يستخدم النظام Laravel 8 وPHP وMySQL، مع جداول وأرقام متزايدة وخدمات تحقق وصلاحيات وحركات مالية مترابطة.

## طريقة التنفيذ

تضمين نسخة محلية من نفس تطبيق Laravel وقوالب Blade وملفات JavaScript/CSS والصور اللازمة، مع تشغيل PHP وقاعدة محلية متوافقة مع MySQL داخل البرنامج. يعرض نفس مسارات النظام على عنوان داخلي مربوط بـ `127.0.0.1`، ويظل التنفيذ والصلاحيات في الخدمات الأصلية. لا يعاد بناء شاشات المصروفات والرواتب والمخزون في واجهة مختلفة.

تهيئة الجهاز لأول مرة أثناء الاتصال تنزل بيانات الحساب وفروعه المسموح بها، وتثبت هوية الجهاز ونسخة الصلاحيات ونسخة الشيفرة والمخطط. لا تتضمن الحزمة بيئة السيرفر `.env` أو كلمات مرور قاعدة الإنتاج أو مفاتيح Firebase/الدفع أو رموز جلسات مستخدمين آخرين. حساب الفرع لا يستقبل بيانات فروع خارج صلاحياته. حساب الإدارة يستقبل البيانات التي تسمح بها صلاحياته الأصلية؛ ربط جهاز POS الحالي بفرع واحد ليس بديلًا عن هذا النطاق.

كل تعديل محلي ناجح يحفظ نتيجته وسجل أمره في معاملة واحدة. الأمر يحمل UUID ثابتًا، الجهاز والحساب والفرع، نوع العملية، المدخلات والمرفقات، وقت التنفيذ، إصدارات البيانات السابقة، ومراجع العمليات التي يعتمد عليها. لا يكفي تخزين طلب POST لإرساله لاحقًا؛ لابد أن تعمل عملية الحساب والتحقق والتحديث والطباعة فعلًا على القاعدة المحلية.

تتولى المزامنة تنفيذ الأوامر على السيرفر بخدمات الأعمال الأصلية وبصلاحيات الحساب الحالية. توجد نتيجة مؤكدة لكل UUID لمنع تكرار الأوامر بعد ضياع الرد. أرقام السجلات المنشأة محليًا تربط بأرقام السيرفر في جدول مراجع، ويطبق الربط على المسارات والمدخلات والمخرجات والمرفقات وأرقام الفواتير المعروضة. لا تدمج صفوف قاعدة العميل مباشرة في الإنتاج ولا تستبدل إجمالي مخزون السيرفر بقيمة جهاز قديمة.

أرصدة المخزون والخزنة تعكس حركات مؤكدة؛ تُرفع حركات البيع والاستلام والمصروف والتحصيل بالترتيب ثم يعاد تنزيل الرصيد المعتمد. تعارض تعديل الصنف/السعر/الموظف أو تقفيل الوردية يحتفظ بالأمر والنتيجة المحلية للمراجعة، ولا يمحوها أو يعيد العملية بمعرف جديد. عمليات الدفع الإلكتروني والتواصل مع التطبيقات والخدمات الخارجية لا توسم ناجحة قبل تأكيد الجهة الخارجية.

العودة من المحلي إلى السيرفر لا تتم بمجرد نجاح اتصال: تكتمل مزامنة الأوامر التابعة، وتعالج التعارضات، وينزل تحديث متسق للبيانات والصلاحيات قبل الانتقال. يظل الجهاز محليًا مع حالة واضحة إذا بقيت عمليات غير مؤكدة. تحديث قاعدة الجهاز لا يستبدل الملفات التي تحتوي على عمليات منتظرة، وتؤخذ نسخة قابلة للاسترجاع قبل ترقيتها.

## معايير التسليم

1. تفتح جميع الشاشات المسموح بها للحساب بنفس القوالب والتصميم عند قطع الشبكة؛ لا ينتقل الجهاز إلى شاشة POS منفصلة.
2. تعمل الإجراءات المسموح بها محليًا وتتغير البيانات والتقارير المرتبطة بها فورًا. تعطل الخدمة الخارجية يظهر بحالته الحقيقية.
3. تستمر المسودات والأوامر والبيانات والمرفقات بعد إغلاق البرنامج وإعادة فتحه دون الإنترنت.
4. عند رجوع الخدمة، يظهر كل أمر مرة واحدة في السيرفر، مع فاتورة وحركة خزنة ومخزون واحدة لكل أثر، حتى بعد فقد الرد أو إعادة تشغيل الجهاز.
5. يجرب سيناريو مرتبط: استلام بضاعة ← بيع ← مصروف ← حضور وسلفة ← تحصيل ← تقفيل وردية أثناء الانقطاع، ثم تقارن المصادر والأرصدة والتقارير على الجهاز والسيرفر بعد المزامنة.
6. يجرب تعارض جهازين على صنف وموظف ووردية، وتغيير صلاحيات الحساب أثناء الانقطاع. لا يحدث فقد أو تكرار أو تجاوز صلاحيات.
7. يختبر التثبيت والترقية على ويندوز فعلي مع نفس حسابات owner/admin/branch ومع طابعة الفرع، وتراجع كل الوحدات قبل اعتبار البرنامج جاهزًا.

## العمل المتبقي

تجهيز runtime ويندوز المحلي وتضمين تطبيق Laravel واعتماد المخطط الفعلي، تصدير بيانات كل نطاق حساب بأمان، تسجيل أوامر جميع الوحدات ومراجعها، استيرادها وتوفيق التعارضات، ثم دمج الانتقال داخل نفس نافذة الداشبورد واختبار التغطية الكاملة. إصلاح الإغلاق والحفظ الحالي يظل أساسًا مطلوبًا، وليس إثباتًا لإنجاز هذه الأجزاء.
